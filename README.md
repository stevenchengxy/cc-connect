# CC Connect

两台电脑安装 CC Connect 并登录获批账号后，可通过固定设备配对码远程操作所选屏幕或双向传输文件。画面、键鼠和文件通过 WebRTC 优先直连。

右上角的状态胶囊可展开查看连接详情。点「设置」可切换简体中文、繁体中文或英文、检查更新和退出账号。首次启动跟随系统语言，手动选择会保存在本机。

0.4.1 起，已批准的管理员登录桌面端后，可直接点击右上角「用户管理」创建邀请码、审批账号及查看中继用量。也可通过浏览器登录[管理后台](https://cc-connect-pair.stevenchengxy19.chatgpt.site/admin)。

## 开始连接

1. 两台电脑分别安装 CC Connect。macOS 打开 DMG，将「CC Connect」拖入「应用程序」，遇到同名应用时选择「替换」。Windows x64 运行 EXE 安装器，按提示完成当前用户安装。
2. 两端都更新至 0.4.12 并登录。新用户向管理员领取 8 位注册邀请码（`XXXX-XXXX`），24 小时内可使用一次。注册后等待管理员审批一次，再在应用内刷新状态。已获批的普通成员可以发起和接受远控与文件传输。
3. 在被控电脑打开「共享此机 → 开启共享」，选择要共享的屏幕。需要操作时勾选「允许对方使用键盘和鼠标」。下次开启共享时，应用会复用本机上该账号的屏幕和权限。「更改共享选项」可更换屏幕或权限。
4. 把本机配对码（`CC-XXXX-XXXX-XXXX`）私发给受邀人。对方在「连接设备」输入后即可按所选权限进入。手动停止共享后，配对码仍保存在这台设备上。再次开启共享才可连接。需要换码时，在空闲时打开「设置 → 本机固定配对码 → 更换配对码」。换码成功后旧码失效。
5. 开启屏幕共享后可以一直等待。第一位连接的获批账号可用原配对码反复重连，断开超过 10 分钟也无需共享端再次选屏。控制端可断开当前连接。共享端点「停止共享」即结束本次授权。退出应用、锁屏、休眠或系统停止采集也会结束共享。
6. 共享端发起的「仅传文件」使用十分钟内有效的单次邀请。旧版兼容码仅供当前临时房间使用。

**macOS 被控端**可在「设置 → 屏幕共享 → 检测屏幕」分别查看录屏和辅助功能状态。如果录屏开关已经打开，但应用仍读不到屏幕，macOS 15.2 及以上可以点「用系统选择屏幕」，在苹果的窗口选中显示器并确认。看到画面尺寸即表示测试成功。检测只在本机取一帧并立即结束。

常规录屏权限可用且显示器相同时，下次开启共享会复用这块屏幕。若 macOS 通过系统选择器授权单次采集，开启下一次共享时仍需在苹果窗口选屏，同一次持续共享中的重连会复用已经选好的画面。系统选择器共享最高 1080p、30 帧/秒。键鼠控制还需要 macOS 辅助功能权限。已勾选键鼠控制时，系统尚未授权也能先共享画面。控制端会显示仅观看的原因。若提示「共享端需授权键鼠」，请在共享端授权后点会话中的「启用键鼠控制」。若提示「共享端未开启键鼠」，请在共享端更改共享选项并勾选键鼠控制，再重新连接。

较早的 macOS 可按诊断显示的应用路径，在系统「隐私与安全性」中为当前 CC Connect 确认录屏和辅助功能授权，再按系统提示重启。macOS 15.0 和 15.1 在屏幕列表读取失败时另提供「选择画面 · 仅观看」。如果系统报告设备策略限制，请联系那台 Mac 的管理者。当前发行包使用临时签名，跨版本更新时 macOS 可能要求重新确认权限。Windows 的系统安全桌面和提升权限的窗口受系统输入权限限制。

## 传输文件

共享端可直接选择「仅传文件」，使用同一个固定码，无需开启录屏或辅助功能。控制端也可对屏幕配对码选择「仅传文件」。两种情况下都只建立文件会话。已经在远程桌面会话中时，可直接使用「发送文件」。

发送方每次选择一个文件，接收方核对文件名和大小后点「另存为…」选择保存位置，也可拒绝。单文件最大 1 GiB，双方校验 SHA-256 后完成保存。打开本机选文件或保存窗口期间会暂停对方的键鼠输入。传输经公共 TURN 中继时，文件同样计入中继流量。

## 画质与延迟

控制端可在连接前或会话中切换接收画质。

| 模式 | 横屏分辨率上限 | 帧率上限 | 视频码率上限 |
| --- | ---: | ---: | ---: |
| 流畅优先 | 1280 × 720 | 30 fps | 4 Mbps |
| 均衡模式（默认） | 1920 × 1080 | 60 fps | 12 Mbps |
| 清晰优先 | 2560 × 1440 | 60 fps | 22 Mbps |

这些数值是编码目标上限。实际效果取决于源屏幕、画面变化、编码硬件、被控端上行带宽和网络拥塞。视频包持续排队、丢包或可用带宽不足时，发送端会调低视频码率、分辨率和帧率，网络恢复后逐步升回所选档位。控制端会在持续移动鼠标时定期通过可靠通道补发最新位置。共享端会合并积压的移动事件，按顺序处理点击和按键。受控画面中只显示一个操作指针；指针嵌入视频的采集方式受视频延迟影响。一般办公从均衡模式开始。阅读小字时可试清晰优先，鼠标反馈拖延或画面频繁冻结时可切到流畅优先。会话底部按可用数据展示直连或中继、实时分辨率、帧率、码率和网络往返时间。往返时间仅衡量网络路径，点击到画面更新还要经过采集、编码、解码和显示。

画面和键鼠使用 WebRTC 加密传输。局域网与跨网配对都通过项目的 HTTPS 服务验证双方账号并交换加密信令。每次重连都会建立新的加密连接。等待时，应用会自动续开临时配对房间。若两台电脑无法直接互访，TURN 可转发加密的媒体和数据。两端仍需足够的带宽。[WebRTC 连接说明](https://webrtc.org/getting-started/peer-connections) · [TURN 指南](https://webrtc.org/getting-started/turn-server) · [WebRTC 安全架构](https://www.rfc-editor.org/rfc/rfc8827.html)

## 网络和隐私

- **自动配对**。双方需联网登录已获批账号。设置留空即可开启共享。服务使用固定设备码定位当前会话，每次开启共享都会创建独立的临时房间和密钥。
- **画面传输**。跨网配对成功后，客户端通过 STUN 发现公网地址，再尝试建立加密的 WebRTC 连接。对称 NAT 或严格防火墙可能允许配对，却阻止画面直连。这类网络需要 TURN 媒体中继，或让两台电脑加入可互访的 VPN。
- **中继与账号**。管理员可为公共中继设置总额度、账号额度与并发限制，额度满足且计量服务可用时签发短期凭据。客户端也可配置自己的 TURN。账号退出、权限撤销或会话失效后会停止连接。
- **本机可见性**。共享时被控端会显示状态。应用没有 Claude 集成。具备屏幕、进程或网络观察权限的工具仍可能识别到活动。传输加密保护链路中的内容。接收方和获准读取本机屏幕的软件都可能看到显示内容。
- **凭据**。设备码可以重复使用，请通过可信渠道发送；手动换码会撤销旧码。旧版兼容邀请仅含本次会话的临时密钥。配对服务可以观察连接地址、时间和流量大小。保存的 TURN 密码由操作系统凭据存储加密。当前版本共享一块屏幕，音频和跨机剪贴板未接入。

## 从源码运行

桌面端使用 Electron。构建需要 Node.js 24。Mac 端需要 Xcode Command Line Tools，Windows x64 端需要 .NET Framework 4.x 自带的 C# 编译器。项目内有两个系统的原生键鼠组件源码。

```sh
npm ci
npm start
```

Mac 上运行 `npm run dist:mac` 可生成临时签名的 Apple Silicon 和 Intel 通用预览 DMG。Windows x64 上运行 `npm run dist:win` 生成 NSIS EXE 安装器。构建产物位于 `release/<版本号>/`。0.4.12 的 Mac 包使用临时签名，Windows 包未进行 Authenticode 签名。

生成 Developer ID 签名的通用 DMG 时，在构建 Mac 的钥匙串安装项目的 Developer ID Application 证书及其私钥，运行 `npm run dist:mac:signed`。有多个匹配身份时，用 `CSC_NAME` 指定证书的 SHA-1 指纹。打包脚本会在生成 DMG 前验证主应用、键鼠组件与系统选屏组件使用同一证书及各自固定的程序标识。后续版本请沿用项目的 Apple Developer 团队。若要同时完成 Apple 公证，可通过 `APPLE_KEYCHAIN_PROFILE` 指定已配置的 notarytool 钥匙串凭据。

## 验证

`npm test` 检查直接配对、证书指纹、邀请密钥、同意与拒绝、WSS 转发以及凭据持久化。`npm run test:desktop` 需要图形桌面环境和支持 node:sqlite 的 Node.js 版本。它使用本机临时数据库注册、审批两个账号，并启动两个带独立临时配置的 Electron 实例，用合成动画窗口验证一次性预授权、复用显示器、逐次确认、仅传文件、实际视频解码、传输统计与停用账号后双端断开。`node scripts/verify-desktop.cjs --weak-network` 可验证模拟限速、丢包和乱序条件下的视频和输入。可选的 `node scripts/verify-desktop.cjs --loopback-relay` 使用本机已有的 `coturn/coturn:4-alpine` Docker 镜像，验证中继凭据续签和限额拒绝。该测试不会采集用户桌面或向系统注入键鼠。

`node scripts/verify-desktop.cjs --reconnect` 使用三个独立的已批准账号，验证原码重连、画面和键鼠恢复、其他账号被拒及手动停止。加长测试 `node scripts/verify-desktop.cjs --reconnect-10m` 会在控制端断开后实际等待 610 秒。

0.3.1 的异网测试在一台 Mac 和独立的 Ubuntu 云主机之间完成了公网配对与授权。两端未配置 TURN，未收到视频帧。另在双 NAT 模拟和强制 TURN 的隔离测试中收到了合成画面。[异网测试记录](https://github.com/stevenchengxy/cc-connect/actions/runs/44282060543)

在这台 Mac 上，还验证了控制通道的鼠标坐标、按键收发、仅观看时的输入隔离和画质切换。Windows 实机键鼠、真实双机跨公网吞吐和延迟仍需在目标设备上验收。

## 更新

从 0.4.1 起，在「设置」打开「软件更新」即可检查、下载并安装新版本。0.3.0 到 0.4.0 的入口在右上角「更新」。下载时显示进度，下载完成后由你点击「安装更新」。安装前需要结束远程会话。

macOS 应安装在 `/Applications/CC Connect.app` 或用户的 `~/Applications/CC Connect.app`。应用内更新会验证下载内容与应用包，关闭现有进程后替换应用并重新打开。也可下载 DMG，通过 Finder 的同名项目提示选择「替换」。

Windows 安装器使用固定的当前用户安装位置。后续 EXE 安装器会更新已注册的旧版安装。早期 ZIP 便携版所在的解压文件夹需要自行管理，安装器升级针对已注册安装。

更新清单使用 Ed25519 签名，客户端校验内置公钥、版本与文件 SHA-256 后安装。发布私钥保存在仓库之外。发布工具 `scripts/sign-release.cjs` 负责为新版本生成签名清单，私钥与凭据应保留在发布环境中。

### 发布新版本

1. 更新 `package.json`、锁文件和下载页中的版本号，运行 `npm test` 与 `npm run test:desktop`。
2. 在对应系统生成安装包。Mac 的 Developer ID 发行构建使用 `npm run dist:mac:signed`，临时签名预览使用 `npm run dist:mac`。Windows 使用 `npm run dist:win`。将产物汇总到 `release/<版本号>/`。
3. 使用发布环境的私钥运行 `npm run release:manifest`。默认密钥位置为 `~/.config/cc-connect-release/signing-key.pem`，也可用 `CC_CONNECT_SIGNING_KEY` 指定。公钥必须与 `src/update-public-key.pem` 匹配。备份私钥；不要将它提交或上传到公开下载位置。
4. 将安装包、`SHA256SUMS.txt` 与 `latest.json` 发布到 GitHub 对应的 `v<版本号>` Release，再将 `website/dist/`（包括生成的 `updates/latest.json`）发布到下载站点。已发布版本的安装包应保持不可变；修复请递增版本号。

自行分发的 fork 应生成自己的 Ed25519 密钥对，并修改 `src/updater.cjs` 和发布脚本里的更新站点与 GitHub 仓库地址。主项目客户端只信任主项目的公钥与下载来源。

Windows 的真实系统升级替换和真实双机公网性能仍需目标设备验收。自动化更新验证使用隔离环境与合成响应。
